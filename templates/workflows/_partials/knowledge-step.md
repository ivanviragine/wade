When project knowledge is enabled, search relevant entries and distinguish
correctness, publication, usefulness, and historical relationships. In this
owning worktree, check claims against committed source with
`wade knowledge check <id> current|contradicted --file <path> --note <reason>`;
non-code proof uses explicitly typed `--evidence-file` input. Utility feedback
uses `wade knowledge feedback <id> useful|not-useful`. Legacy votes establish no
correctness authority. Capture durable learnings only when they do not repeat
existing documentation. List pending observations with `wade knowledge proposals
list`; accept only a verified matching parent/task/content proposal, then assess
fresh committed proof. Never adopt unrelated feedback or edit main's spool.
Commit all knowledge changes before closing review. After sync, read
`wade knowledge reconcile --against HEAD --check`; done repeats this read-only
check and refuses corrupt or uncommitted knowledge. The command-support skill
contains the proof types and recovery commands.
